# 論点別の調査・事業者比較・規制との対応表

既存の文書データとブラウザ内の保存先を利用する、追加の3画面です。特定の事業者を利用者自身の会社として扱いません。

| 画面 | URL | 内容 |
| --- | --- | --- |
| 論点一覧・論点別の資料 | `/topics`、`/topics/:topicId` | 法令・ガイドライン・JVCEA規則・事業者資料・Q&Aを共通の論点で分類し、種類・事業者・語句で絞り込みます。 |
| 事業者間の規約比較 | `/provider-compare` | 左右の事業者・文書・項目を選択し、原文を横並びで読みます。狭い画面では縦並びになります。 |
| 規制と公表資料の対応表 | `/regulation-map` | 規制の項目を行、事業者を列として、候補と確認した対応づけを表示します。根拠メモ、確認日の記録、再確認、解除ができます。 |

ホームとサイドバーの「調べる・比較する」から開きます。論点や絞り込み、比較する項目はURLに保持します。

## 分類と対応づけ

`research-model.mjs` の10論点は、本文と見出し（親見出しを含む）の語句による分類です。空見出し・削除済み項目は結果に含めません。資料の記載内容や法的な適用範囲を自動判定するものではありません。

対応表の候補は、同じ論点で共通の語句を含む事業者資料の上位8件です。規制への適合を示すものではなく、利用者が原文を確認して対応づけを記録します。候補にない資料も、その事業者の全資料から選択できます。

確認時の本文フィンガープリントを保存し、規制または事業者資料の本文が変われば「本文変更・再確認」、参照元がなくなれば「参照元が見つかりません」と表示します。分類語句がなくなる変更があっても、確認した対応づけは引き続き確認できます。

## 保存・移行

記録は既存のIndexedDBにある文書データの `researchMappings` 配列に保存します。文書として列挙されない配列形式とし、従来の全文検索や文書一覧に混入させません。

ホームの「記録を書き出す」「記録を読み込む」に対応しています。出力は記録形式バージョン2で、旧バージョン1も読み込めます。同じIDは更新日時が新しい方を保持し、解除済みの記録は削除マーカーにより古いバックアップから復活しないようにします。既存のチェックリスト・コメント・リスト・社内規程には変更を加えません。

確認日時はUTCで保存し、画面では日本時間の日付を表示します。記録やメモを外部サービスへ送信する処理はありません。

## 開発・検証

このチェックアウトには元のVueソースがないため、読みやすい追加ソースをこのフォルダで管理し、ハッシュ付きモジュールとCSSを生成して配信エントリに組み込みます。既存のVueランタイム・ルーター・保存処理・HTMLサニタイザーを共有します。追加のnpm依存関係はありません。

```sh
node scripts/build-research.mjs
node scripts/verify-research.mjs
node scripts/verify-sbivc.mjs
```

SBI資料自体を再生成する場合は、`import-sbivc.py` と `integrate-sbivc.mjs` の後に上記のビルド・検証を実行します。ビルドは同じ入力から同じ出力を生成します。元のアプリソースから配信し直す場合は、この追加モジュール・ルート・ナビゲーション・記録形式の変更を元ソース側にも反映してください。

検証では実際の同梱資料と配信コードを使い、各論点の分類、事業者別の候補、対応づけ・本文変更・参照元削除、旧形式の読込み、バックアップの往復、メモの新旧判定、解除の保持、同梱データ更新後の記録保持を確認します。
