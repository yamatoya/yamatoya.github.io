# 論点別の調査・事業者比較・規制との対応表

既存の文書データとブラウザ内の保存先を利用する、追加の7画面です。特定の事業者を利用者自身の会社として扱いません。

| 画面 | URL | 内容 |
| --- | --- | --- |
| 論点一覧・論点別の資料 | `/topics`、`/topics/:topicId` | 法令・ガイドライン・JVCEA規則・事業者資料・Q&Aを共通の論点で分類し、種類・事業者・語句で絞り込みます。 |
| 事業者間の規約比較 | `/provider-compare` | 左右の事業者・文書・項目を選択し、原文を横並びで読みます。狭い画面では縦並びになります。 |
| 規制と公表資料の対応表 | `/regulation-map` | 規制の項目を行、事業者を列として、候補と確認した対応づけを表示します。根拠メモ、確認日の記録、再確認、解除ができます。 |

ホームとサイドバーの「資料を探す」「比較する」「対応を確認する」から開きます。論点や絞り込み、比較する項目はURLに保持します。

## 分類と対応づけ

`research-model.mjs` の10論点は、本文と見出し（親見出しを含む）の語句による分類です。空見出し・削除済み項目は結果に含めません。資料の記載内容や法的な適用範囲を自動判定するものではありません。

対応表の候補は、同じ論点で共通の語句を含む事業者資料の上位8件です。規制への適合を示すものではなく、利用者が原文を確認して対応づけを記録します。候補にない資料も、その事業者の全資料から選択できます。

確認時の本文フィンガープリントを保存し、規制または事業者資料の本文が変われば「本文変更・再確認」、参照元がなくなれば「参照元が見つかりません」と表示します。分類語句がなくなる変更があっても、確認した対応づけは引き続き確認できます。

## 保存・移行

記録は既存のIndexedDBにある文書データの `researchMappings` 配列に保存します。文書として列挙されない配列形式とし、従来の全文検索や文書一覧に混入させません。

ホームの「記録を書き出す」「記録を読み込む」に対応しています。出力は記録形式バージョン4で、旧バージョン1・2・3も読み込めます。同じIDは更新日時が新しい方を保持し、解除済みの記録は削除マーカーにより古いバックアップから復活しないようにします。既存のチェックリスト・コメント・リスト・社内規程には変更を加えません。

確認日時はUTCで保存し、画面では日本時間の日付を表示します。記録やメモを外部サービスへ送信する処理はありません。

## 開発・検証

このチェックアウトには元のVueソースがないため、読みやすい追加ソースをこのフォルダで管理し、ハッシュ付きモジュールとCSSを生成して配信エントリに組み込みます。既存のVueランタイム・ルーター・保存処理・HTMLサニタイザーを共有します。追加のnpm依存関係はありません。

```sh
node scripts/build-research.mjs
node scripts/verify-history.mjs
node scripts/verify-sbivc.mjs
```

SBI資料自体を再生成する場合は、`import-sbivc.py` と `integrate-sbivc.mjs` の後に上記のビルド・検証を実行します。ビルドは同じ入力から同じ出力を生成します。元のアプリソースから配信し直す場合は、この追加モジュール・ルート・ナビゲーション・記録形式の変更を元ソース側にも反映してください。

検証では実際の同梱資料と配信コードを使い、各論点の分類、事業者別の候補、対応づけ・本文変更・参照元削除、旧形式の読込み、バックアップの往復、メモの新旧判定、解除の保持、同梱データ更新後の記録保持を確認します。

## 過去の改定・改正とサービスの絞り込み

`/provider-history` に事業者規約の新旧比較、`/revision-impacts` に改正の影響一覧を追加しています。公式告知66件と原本の収録範囲は [履歴アーカイブ](../docs/provider-history/2026-11-23/README.md) を参照してください。過去の全文や任意の2時点間の全文比較を復元する機能ではありません。公式の対照表・告知が示す改定前後を表示します。

法令・規則等は既存の改正履歴から変更された条文IDを抽出し、そのIDに対応づく事業者資料・確認記録・社内規程を表示します。事業者の過去改定は文書単位の確認候補です。変更された箇所と現行の条文IDとの一致を推定しません。対応づけや確認記録がない場合は未判定です。既存の改正への社内対応も参照できます。

改正ごとの担当者・期限・判断メモ・確認状況は `researchImpactReviews` 配列に保存し、バックアップにも含めます。資料のフィンガープリントが変わると要再確認になります。

対象サービスは `services.mjs` の分類を利用し、論点検索・事業者間比較・対応表・履歴・影響一覧で共通して絞り込めます。専用規約の対象サービス、共通方針、本文や見出しの言及、総合文書の対象サービスの順に分類します。実際に各事業者が提供するサービスの一覧や、法令の適用判断を示すものではありません。共通資料を含めるか選択でき、未分類も確認できます。条件はURLに保存し、調査画面間で引き継ぎます。

## 用語比較と調査レポート

`/definitions` で任意の用語を検索し、文書ごとの定義候補を左右に選択できます。事業者・資料の種類・サービスで絞り込めます。「単なる言及も含める」を選ぶと定義表現以外の箇所も表示します。定義表現・定義の見出しからの機械的な候補であり、適用範囲の同一性を判定しません。括弧内の句点で引用を切らず、全文・原本へのリンクから文脈を確認できます。

`/research-report` には、論点の資料・事業者比較・新旧比較・改正の影響・用語比較から必要な項目を追加できます。表題・作成者・調査の目的・項目ごとの判断メモを編集し、順番の変更や項目の除外ができます。HTML・Markdownの書き出しと印刷（ブラウザーのPDF保存）に対応します。出典URL・保存原本URL・資料取得日・原本ページ（ある場合）・追加時点を収録します。取得日を確認できない場合は未記録と表示します。

追加した引用はその時点のスナップショットです。元資料が変わった場合や見つからない場合はレポート画面と書き出しに表示します。元の画面から再追加すると引用を更新し、判断メモを保持します。改正の影響は保存済みの確認記録を使うため、未保存のフォーム入力は先に保存してください。

保存先は `researchReport` 配列です。表題等の設定も同じ配列に含めます。除外した項目は削除マーカーを残し、古いバックアップから復活しないようにします。レポート作成・書き出しはブラウザー内で処理し、外部サービスへ送信しません。出力には入力した担当者・社内のメモも含まれるため、共有する内容はプレビューで確認できます。

```sh
node scripts/verify-report.mjs
```

## UIと作業の流れ

アプリの目的は、公表された規制・資料を根拠として調査し、比較し、自社で必要な対応を検討・記録することです。公表資料と自社の対応記録は区別します。

入口は `ux-model.mjs` に集約した4分類です。「資料を探す」（全文検索・文書一覧・論点）、「比較する」（事業者間・新旧・用語）、「対応を確認する」（改正の影響・対応づけ・社内対応・規程・役割）、「レポート」（調査レポート・対応集計・保存した条文）に整理しています。

ホームは全文検索と作業の入口を中心とし、全機能のカードや文書一覧を重ねて表示しません。文書一覧は `/library`、比較の入口は `/compare`、対応確認の入口は `/review` です。従来の文書・条文・改正・比較のURLも引き続き利用できます。`/?q=...` も従来の検索を利用します。

デスクトップではサイドバーで現在の分類の詳細だけを表示します。文書の種類別目次はライブラリと文書閲覧時に表示します。モバイルではメニューと横スクロールできる分類内のタブを利用します。新旧比較・影響一覧にはモバイル用の記録選択欄を設け、長い本文を読み終えずに別の記録を選べます。

研究画面の主な条件はそのまま表示し、補助条件は「詳細条件」にまとめます。設定中の条件は常にチップで表示し、個別解除・一括解除できます。全文検索も結果件数を常に表示し、検索範囲の調整と過去の改正での出現は開いて確認する構成です。資料カードの出典・保存操作は必要なときに開けます。

`workspace.css` に配色・文字・余白・入力欄・ボタン・カードの共通トークンとレイアウトをまとめ、既存画面にも適用します。編集や判断の内容、保存データ、バックアップ形式はUIの整理によって変更しません。バックアップとデータ管理はホームおよびライブラリ下部の開閉欄に残しています。

```sh
node scripts/verify-ux.mjs
```

## 引用カードとSlack等でのリンク共有

条文ページの操作欄、調査画面の資料カードにある「出典・保存の操作」から「引用を共有」を開けます。本文を選択してから開くと、同じ資料内の一節を取り込めます。選択していない場合は短い抜粋を初期表示します。480文字以内で、原文に連続して含まれる文言のみ指定できます。マーカー／シンプルを選び、プレビューを確認してPNG保存・画像コピー・リンク付き引用のコピーができます。対応している端末では共有メニューも使えます。

引用画像はブラウザーのCanvasで作成します。抜粋、文書名、条番号、資料取得日（記録がある場合）、選択中の過去時点を掲載します。担当者・確認状況・判断メモなどの記録は対象にしません。画像の自動アップロードやSlackへの自動投稿は行いません。

任意に選んだ抜粋は、そのまま画像として共有します。リンクのOGPは文書ごとの表紙です。同じ文書内でも抜粋は利用者ごとに異なり、静的配信ではリンクのプレビューに個別の抜粋を動的に反映しません。

`/share/<docId>/` は公開レジストリから生成したHTMLです。OGPタグと1200×630のPNGを最初から含むため、JavaScriptを実行しないクローラーも文書名・表紙を取得できます。人が開いた場合は既知の条文IDと有効な `asof` 日付だけを引き継いで元の収録本文に進みます。ブラウザー内で追加した文書・対応記録から公開ページを作ることはありません。従来のSPAの深いURLは404経由なので、OGPを使いたい場合は新しい共有用リンクをコピーしてください。

公開レジストリを更新した場合は、共有ページも再生成します。`Pillow` と日本語フォントを利用します。macOSではシステムフォントを使い、その他の環境では `SHARE_FONT` を日本語のTTF/OTFフォントに設定します。フォント自体は配信しません。

```sh
# 必要なら SHARE_PYTHON でPillowのあるPythonを指定
node scripts/build-share-pages.mjs
node scripts/build-research.mjs
node scripts/verify-share.mjs
```

OGPをSlackで表示するには、この変更を公開する必要があります。表示にはSlack側のキャッシュやワークスペースの設定も関係します。ローカルの検証では、OGPの静的HTML・PNG・遷移先・画像出力を確認します。
